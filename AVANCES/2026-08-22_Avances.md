## ✅ Cambio 2: Sistema Antireinicios Automático (LISTO)

### Problema
Los cortes de luz de ~30 minutos causaban que:
1. El token renovado (en memoria) se perdía al apagarse
2. Al encender, leía el `session_master.json` viejo con un token ya rotado
3. Microsoft rechazaba con `invalid_grant` → sistema muerto hasta intervención manual

### Solución Implementada (3 capas de protección)

#### Archivos modificados:
- `auth_http.py` — Escritura atómica + retry + refresh inmediato al arrancar
- `main.py` — Auto-refresh on-demand cuando falla un CID request

#### Capa 1: Escritura Atómica (`_save_session`)
- Cada vez que el daemon renueva tokens, los guarda **atómicamente** en `session_master.json`
- Usa patrón write-to-tmp + rename: escribe en `.tmp`, hace `fsync()` a disco, y luego `os.replace()`
- Si la luz se corta **durante** la escritura, el archivo original queda intacto

#### Capa 2: Retry con Backoff Exponencial (`refresh_access_token`)
- Ahora tiene 3 reintentos con esperas de 15s, 30s, 45s
- Crítico para después del corte de luz: la red puede tardar en estabilizarse
- Si el error es `invalid_grant` (permanente), no reintenta y marca como fallido

#### Capa 3: Refresh Inmediato al Arrancar (`start_daemon`)
- **ANTES:** El daemon esperaba 10-13 horas antes de renovar por primera vez
- **AHORA:** En cuanto arranca, renueva el token INMEDIATAMENTE
- Esto significa que después de un corte de luz, el sistema está operativo en ~5 segundos

#### Capa 4: Auto-Refresh On-Demand (`main.py` - `/check_pid`)
- Si un cliente pide un CID y Microsoft responde 401/403:
  1. Renueva el token automáticamente
  2. Reconstruye los headers con el nuevo token
  3. Reintenta la petición CID
  4. El cliente obtiene su CID sin saber que hubo un problema
- **ANTES:** El 401 mataba la petición y el cliente veía error
- **AHORA:** Se auto-heala y el cliente ni se entera

## ✅ Cambio 5: Hot-Reload y Fix OCR en Telegram (LISTO)
- **Problema:** El bot fallaba al leer pantallas (leía `0110000`) y daba error "UNAUTHORIZED" porque no compartía el mismo archivo de sesión, obligando a usar Portainer para actualizar tokens.
- **Solución:**
  1. Se implementó un endpoint `/api/update_session` en el backend.
  2. El bot ahora acepta que el usuario le envíe directamente el archivo `session_master.json` como documento, inyectándolo al backend en tiempo real (Cero caídas).
  3. Se añadieron dos filtros agresivos de imagen (`LCD_Screen` y `LCD_Aggressive`) en `ocr.js` para destruir el ruido de los píxeles de los monitores antes de pasar por Tesseract.

## ✅ Cambio 6: Sistema "Inmortal" (Auto-Extractor Indetectable + Cloudflare)
- **Problema:** Si el token caía mientras el usuario estaba de viaje, el sistema moría porque dependía de extraer tokens manualmente en su PC local.
- **Solución Definitiva:**
  1. Se creó el microservicio independiente `getcid_auto_extractor` (Ubuntu + x11vnc + Python).
  2. Se usó `undetected-chromedriver` para navegar Microsoft falsificando la huella digital. Esto evita que Microsoft arroje CAPTCHAs en el 99% de los casos.
  3. El sistema intercepta el token `DPoP` con `selenium-wire` y actualiza la sesión automáticamente en caliente.
  4. **Túnel Cloudflare:** Si Microsoft pide verificación SMS obligatoria, el contenedor levanta un túnel de `cloudflared` y envía un enlace HTTPS público al Telegram del administrador. El usuario toca el enlace desde su celular (en cualquier lugar del mundo), ve la pantalla remota (noVNC), introduce el SMS y salva el sistema.

## ✅ Cambio 7: Gatillo de Emergencia Remoto (Telegram) (LISTO)
- **Problema:** El usuario necesitaba una forma de forzar la renovación automática desde su teléfono, sin tener que entrar al servidor por SSH a borrar el archivo `session_master.json`.
- **Solución:**
  1. Se creó el endpoint `POST /api/force_extraction` en el backend `main.py`, el cual vacía el token local y dispara al `auto_extractor` inmediatamente.
  2. Se vinculó el botón **"🔄 Renovar Token"** del menú de administrador en Telegram para que llame directamente a este endpoint de extracción forzada.
  3. Ahora el administrador puede reiniciar todo el ciclo de autenticación con un solo toque desde Telegram.

## ✅ Cambio 8: Sincronización Final de Telegram con la v2.0 (LISTO)
- **Problema:** Tras migrar a GETCID 2.0 (Zero-Browser), muchos botones del menú de Telegram (como *Apagar Sistema*, *Device Auth*, *Estado Token*) fallaban o apuntaban a URLs antiguas. Además, el botón *Renovar Token* crasheaba (Error 500) porque el endpoint `/api/force_extraction` en `main.py` exigía una validación de seguridad fantasma.
- **Solución:**
  1. Se eliminó la dependencia `Security(get_api_key)` del endpoint de extracción en `main.py` para permitir la comunicación interna.
  2. Se limpió `bot.js`, eliminando los comandos obsoletos que dependían de Playwright en el contenedor principal.
  3. Se recablearon los comandos `Estado Sistema` y `Estado Token` para que lean el nuevo endpoint `/status` del demonio `auth_http.py`.
  4. Se actualizó la sección de Ayuda Admin para reflejar los comandos exactos disponibles.
